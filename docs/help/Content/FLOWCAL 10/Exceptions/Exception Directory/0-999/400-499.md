## 400 - 402

#### <a href="javascript:void(0);" class="MCToggler MCTogglerHead MCTogglerHotSpot MCToggler_Open toggler togglerexception MCTogglerHotSpot_ MCTogglerHotSpot_exception MCHotSpotImage" data-mc-targets="00400">

<img src="data:image/gif;base64,R0lGODlhEAAQAPcAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAACH5BAEAAP8ALAAAAAAQABAAAAgdAP8JHEiwoMGDCBMqXMiwocOHECNKnEixosWBAQEAOw==" class="MCToggler_Image_Icon" data-mc-alt2="Open" width="16" height="11" alt="Closed" />400 Operational meter factor variance limit exceeded</a>

<div class="drop-down" style="display: none;" mc-target-name="00400">

This exception is generated upon import of prove reports into FLOWCAL through PFX files when the prove data violates the Operational limit configured for Meter Factor Change Between Proves on Contractual Limits. To enable this validation, the Operational field for Meter Factor Change Between Proves must be populated. The operational limit configuration must be effective for the date of the batch the prove data is applied to.

This exception is generated when the meter factor in the prove report is different from the existing meter factor for the batch date by more than the operational limit. This exception is generated for all batches the violating prove data was applied to.

For example, liquid meter PROVE_METER has 4 weekly batches in August 2017 with effective dates 8/1/2017 7:00:00, 8/8/2017 7:00:00, 8/15/2017 7:00:00, and 8/22/2017 7:00:00. There is a contractual limit configuration for this meter with effective dates 1/1/2017 7:00:00-1/1/2018 7:00:00. On the contractual limit configuration, the operational limit for Meter Factor Change Between Proves is set to 0.0010. Before prove reports are imported for August, the meter factor is 0.9999 for all four August batches. Then 3 prove reports each dated 8/1/2017 10:35:22, 8/8/2017 09:14:53, and 8/15/2017 9:45:44 are imported and applied as follows:

<div class="drop-down" style="display: none;" mc-target-name="00402">

This exception is generated upon meter data import if both the meter characteristic in effect and the configuration data being imported have NULL calculation method. The exception is generated for periodic records to which the violating characteristic record applies.

For example, a gas meter has a characteristic record from 5/16/2017 12:00:00 to 9/1/2017 9:00:00 that has turbine meter type but NULL calculation method by mistake. A CFX file with configuration data enabled and periodic records dated 6/1/2017 9:00:00 and 7/1/2017 9:00:00 are imported. The configuration section of the CFX file has NULL for calculation method. When the import is done and data is saved, a characteristic record is split at 6/1/2017 9:00:00 that has NULL calculation method. Exception 402 is generated for 6/1/2017 9:00:00 and 7/1/2017 9:00:00 periodic records as the 6/1/2017 9:00:00 characteristic record applies to periodic records.
